# 원장 기록 (Product Requirement)

등록 건의 원장 기록 요청, 상태, 결과 저장, 실패 재시도, 무효 처리, 플랫폼 노출 조건, 원장 연동 구조에 대한 제품 요구사항이다. 열 구성과 근거 표기는 `01-관리자 포털.md`와 같다.

| ID | 요구사항 | based_on | 비고 |
| --- | --- | --- | --- |
| PR-019 | 관리자가 최종 확인 화면에서 기록을 요청하면 해당 등록 건을 기록 대기 상태로 저장하고 원장에 기록을 요청한다 | BR-005 — 원장 기록 상태 구분 | |
| PR-020 | 등록 건의 원장 기록 상태를 기록 대기, 기록 완료, 기록 실패 중 하나로 구분해 등록 이력과 등록 건 상세에 표시한다 | BR-005 — 원장 기록 상태 구분 | |
| PR-021 | 원장 기록이 완료되면 기록 번호(tx 해시)와 확정 결과를 서비스에 저장하고 상태를 기록 완료로 바꾼다. 기록에 실패하면 상태를 기록 실패로 바꾼다 | BR-006 — 원장 기록 결과 저장 | |
| PR-022 | 저장된 기록 번호는 등록 이력과 등록 건 상세에서 관리자가 확인할 수 있게 표시한다 | BR-006 — 원장 기록 결과 저장, BR-008 — 등록 이력 조회 | |
| PR-023 | 원장에 기록한 내용을 수정하거나 삭제하는 기능을 제공하지 않는다. 변경이 필요하면 추가 기록으로만 남긴다 | BR-006 — 원장 기록 결과 저장 | |
| PR-024 | 기록 실패 건을 선택해 재시도할 수 있다. 재시도하면 원장에 기록을 다시 요청하고 상태를 기록 대기로 바꾼 뒤 결과에 따라 갱신한다. 재시도 횟수는 제한하지 않는다 | BR-007 — 실패 건 재시도 | |
| PR-025 | 기록 완료된 등록 건 중 잘못 등록된 건을 골라 무효 처리를 요청할 수 있다. 요청 전에 무효 처리 대상 건을 확인하는 화면을 보여 준다 | BR-011 — 무효 처리 | |
| PR-026 | 무효 처리를 실행하면 기존 등록 기록은 수정·삭제하지 않고 '무효' 기록을 원장에 추가한다 | BR-011 — 무효 처리 | |
| PR-027 | 플랫폼의 상품 노출 조회는 원장 기록 상태가 기록 완료이면서 무효 처리되지 않은 등록 건만 대상으로 한다. 기록 대기·기록 실패 건과 무효 처리된 건은 노출하지 않는다 | BR-005 — 원장 기록 상태 구분, BR-011 — 무효 처리 | |
| PR-028 | 원장 연동 기능은 체인 종류에 의존하는 부분을 별도 모듈로 분리해, 연동 대상 블록체인을 설정과 해당 모듈 교체만으로 바꿀 수 있게 한다 | BR-015 — 원장 연동 구조 | |
| PR-029 | 원장 연동은 Base(이더리움 EVM 호환 L2) 메인넷을 대상으로 등록·검증·이력 조회를 수행한다 | BR-015 — 원장 연동 구조 | |
