# 03. 범위 (Phase 1 MVP)

**목표:** 관리자가 고유번호를 등록하면 원장에 기록되고, 그 기록으로 플랫폼에 상품이 노출되며, 누구나 진위를 조회할 수 있다.

```
[관리자 등록/검수]  (Phase 1)
↓
[원장 기록]         (Phase 1)
↓
[플랫폼 상품 노출]   (Phase 1)
↓
[유저 거래]         (Phase 2)
```

## 설계 원칙

세부 정책은 `BR/08-정책.md`(POLICY-001~005)를 따른다.

| # | 원칙 | 내용 | 정책 |
| --- | --- | --- | --- |
| 1 | 원장이 진위의 기준 | 진위·소유는 원장을 기준으로 하고, 가격·호가·결제처럼 자주 바뀌는 정보는 서비스 자체 저장소에서 관리한다 | POLICY-001 |
| 2 | 등록 건이 연결고리 | 원장 기록이 완료된 등록 건만 플랫폼에 노출한다 | POLICY-002 |
| 3 | 기록은 추가만 가능 | 원장에 한번 기록된 내용은 수정·삭제하지 않고 추가로만 남긴다. Phase 1은 '등록'과 '무효'(오등록 정정용) 기록을 남기고, Phase 2에서 '판매 등록', '판매 완료', '소유권 이전' 기록을 추가한다 | POLICY-003, POLICY-004 |
| 4 | 개인정보 미기록 | 고유번호는 원문이 아닌 복원할 수 없는 변환값(해시+salt)으로 저장하고, 유저는 익명 ID만 사용한다 | POLICY-005 |

## In Scope

| 영역 | 기능 | 상세 |
| --- | --- | --- |
| 관리자 | 로그인 | 단일 역할, 회원가입 없이 운영 측에서 미리 만들어 준 계정으로 이용 |
| 관리자 | 상품 마스터 관리 | 브랜드, 모델, 이미지 등록. 원장 기록이 연결된(등록 완료된) 상품은 수정·삭제 불가, 미연결 상품만 자유롭게 수정·삭제 (POLICY-006) |
| 관리자 | 고유번호 등록 | 단건 입력 및 일괄 등록(파일 업로드 등), 형식 확인(브랜드/상품별 상이, Phase 1은 최소 검증만, POLICY-007), 중복 검사 (서비스 내 등록 내역 + 원장), 원장 기록 요청 전 최종 확인 화면 (POLICY-008) |
| 관리자 | 원장 기록 요청/상태 | 원장 기록 요청 및 상태 표시 (상태 정의는 `규칙/03-용어집.md` §2 참조) |
| 관리자 | 실패 건 재시도 | 관리자가 직접 재시도, 횟수 제한 없음 (POLICY-009) |
| 관리자 | 등록 이력 조회 | 등록자, 등록 시각, 기록 번호(tx 해시), 고유번호/상품명/등록자/기간 기본 검색·필터, 등록·무효 처리 등 관리자 작업 이력 |
| 관리자 | 무효 처리 | 잘못 등록된 건에 '무효' 기록을 추가 (기존 등록 기록은 수정·삭제하지 않음). 무효 처리된 건은 플랫폼 노출에서 제외 (POLICY-010) |
| 관리자 | 조회 횟수 모니터링 | 고유번호별 진위 조회 횟수를 기록하고 관리자가 확인 가능 (번호 복제 등 이상 징후 파악용 최소 기능, 알림·통계 대시보드는 Phase 2+) (POLICY-011) |
| 원장 | '등록' 기록 남기기 | 고유번호 변환값, 상품, 등록 시각을 기록 (개인정보 제외) |
| 원장 | 기록 결과 저장 | 기록 번호와 확정 결과를 서비스에 저장 |
| 원장 | 원장 연동 구조 | 등록·검증·이력 조회 기능을 제공하며, 연동 대상 블록체인은 이더리움(EVM 계열)로 시작하되 다른 EVM 호환 체인(L2 포함)으로 교체할 수 있는 구조 (POLICY-013) |
| 원장 | 운영 환경 | 이더리움 테스트넷 환경으로 한정 |
| 플랫폼 | 상품 목록/상세 | 기록 완료된 등록 건만 노출, 조회 전용, 로그인 불필요 |
| 플랫폼 | 고유번호 진위 조회 | 원장 대조 결과를 '정품'으로 명시 표시, 결과 유형(정품/무효 처리됨/미등록), 등록 시각, 기록 확인 링크 표시 (POLICY-012) |
| 플랫폼 | 상품 상태 | '등록됨'만 구현하고, '판매 중'·'판매 완료'는 정의만 해 둔다 |
| 공통 | 관리 대상 정보 정의 | 등록 건, 상품, 관리자, 원장 기록 결과 |
| 공통 | 조회 기능 명세 작성 | 진위 조회·상품 조회 기능의 입력과 결과를 문서로 정리 |
| 공통 | 작업 이력 | 누가 무엇을 등록했는지 남김 |

## 완료 기준 (Definition of Done)

| # | 기준 |
| --- | --- |
| 1 | 관리자가 고유번호를 등록하면 원장에 기록되고 기록 번호가 서비스에 남는다 |
| 2 | 같은 고유번호는 재등록되지 않는다 |
| 3 | 일반 유저가 고유번호로 조회하면 원장 기준의 진위 결과가 나온다 |
| 4 | 기록 완료되지 않은 등록 건은 플랫폼에 노출되지 않는다 |
| 5 | 연동 대상 블록체인만 교체해서 다른 블록체인으로 붙일 수 있다 |

## Phase 1 / Phase 2 비교

| 구분 | Phase 1 (MVP) | Phase 2 |
| --- | --- | --- |
| 핵심 | 등록 → 원장 기록 → 노출/진위 조회 | 중개거래 플랫폼 완성 |
| 사용자 | 관리자, 비로그인 조회자 | 일반 유저, 협력사 |
| 원장 기록 유형 | '등록', '무효' | + '판매 등록', '판매 완료', '소유권 이전' |
| 거래 | 없음 (조회 전용) | 입찰, 즉시구매, 에스크로, 정산 |
| 블록체인 환경 | 이더리움 테스트넷 | 이더리움(또는 EVM 호환 L2) 실서비스용 |
