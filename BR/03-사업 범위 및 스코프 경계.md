# 03. 사업 범위 및 스코프 경계 (Phase 1 MVP)

**목표:** 관리자가 고유번호를 등록하면 원장에 기록되고, 그 기록으로 플랫폼에 상품이 노출되며, 누구나 고유번호로 정품 인증 결과를 조회할 수 있다.

서비스 전체 지향점은 `01-서비스개요.md`에서 다루고, 이 문서는 Phase 1에서 실제로 제공하는 범위와 제외 범위를 정한다. Phase 1의 진위 조회는 고유번호를 원장에 기록된 정보와 대조해 정품 인증 결과를 보여 주는 기능이며, 실물 검수와 위조품 거래 차단은 Phase 1 범위가 아니다.

```
[관리자 등록/확인]  (Phase 1)
↓
[원장 기록]         (Phase 1)
↓
[플랫폼 상품 노출]   (Phase 1)
↓
[유저 거래]         (Phase 2)
```

## 설계 원칙

세부 정책은 `BR/08-업무 규칙 및 정책.md`의 POLICY를 따른다.

| # | 원칙 | 내용 | 정책 |
| --- | --- | --- | --- |
| 1 | 원장이 진위의 기준 | 진위·소유는 원장을 기준으로 하고, 가격·호가·결제처럼 자주 바뀌는 정보는 서비스 자체 저장소에서 관리한다 | POLICY-001 |
| 2 | 등록 건이 연결고리 | 원장 기록이 완료된 등록 건만 플랫폼에 노출한다 | POLICY-002 |
| 3 | 기록은 추가만 가능 | 원장에 한 번 기록된 내용은 수정·삭제하지 않고 추가로만 남긴다. Phase 1은 '등록'과 '무효'(오등록 정정용) 기록을 남기고, Phase 2에서 '판매 등록', '판매 완료', '소유권 이전' 기록을 추가한다 | POLICY-003, POLICY-004 |
| 4 | 개인정보 미기록 | 고유번호는 원문이 아닌 복원할 수 없는 변환값(해시+salt)으로 저장하고, 유저는 익명 ID만 사용한다 | POLICY-005 |
| 5 | 고유번호가 식별자, 칩은 복제 방지 매체 | 고유번호는 모든 등록 건의 식별자이며 칩·QR 등 매체에 담을 수 있다. 번호는 복사할 수 있으므로 '정품'은 서명 칩 검증을 통과한 조회에만 표시하고, 서명이 없는 조회는 원장 등록 여부만 안내한다. Phase 1은 제조사가 출고 시점에 서명 칩을 부착한 신규 제품만 등록하며, Phase 1의 칩 비용은 운영사가 부담한다 | POLICY-012, POLICY-016, POLICY-017, POLICY-018 |

## Phase 1 범위 구분

Phase 1은 파트너 1~2곳과 실거래 환경에서 핵심 흐름을 검증하는 것을 우선한다. 범위를 두 덩어리로 나눈다.

| 구분 | 내용 |
| --- | --- |
| 필수 (핵심 흐름) | 관리자 로그인, 상품 마스터, 고유번호 등록(단건·일괄, 최종 확인), 원장 기록·상태·실패 재시도, 무효 처리, 등록 이력·작업 이력, 웹 진위 조회(서명 NFC 칩 스캔 시 서명 검증·원장 대조, QR 스캔·번호 입력 시 원장 등록 여부), 서명 NFC 칩 부착 제품 등록, 조회 횟수 확인 |
| Phase 2로 보류 | 모바일 앱, 제조사용 관리자 시스템, 협력사 API 연동, 거래 시점 검증 수수료, 소유권 이전, 감정사 연동 기능, 기존 제품 등록(칩 후부착·감정 기반 등록) |

Phase 1은 제조사가 출고 시점에 서명 NFC 칩을 부착한 신규 제품만 등록한다. 등록 근거(제조사 협력 자료) 확인은 시스템이 아니라 운영사의 수작업으로 한다.

| 플랫폼 | 상품 목록/상세 | 기록 완료된 등록 건만 노출, 조회 전용, 로그인 불필요 |
| 플랫폼 | 칩 스캔 진위 조회 | 제품에 부착된 인증 칩을 스캔해 칩 서명 검증과 원장 대조를 모두 통과하면 '정품'으로 표시. 결과 유형(정품/무효 처리됨/미등록), 등록 시각, 기록 확인 링크 표시 (POLICY-012, POLICY-017) |
| 플랫폼 | 번호 입력·QR 스캔 조회 | 고유번호를 직접 입력하거나 서명 없는 QR을 스캔하면 '정품'이 아닌 원장 등록 여부만 표시. 결과 유형(등록된 번호/무효 처리됨/미등록) (POLICY-016) |
| 제품 | 인증 칩 부착 | 제조사가 출고 시점에 제품에 서명 기능이 있는 NFC 칩을 부착하고, Phase 1의 칩 비용은 운영사가 부담 (POLICY-017, POLICY-018) |
| 플랫폼 | 상품 상태 | '등록됨'만 구현하고, '판매 중'·'판매 완료'는 정의만 해 둔다 |
| 공통 | 관리 대상 정보 정의 | 등록 건, 상품, 관리자, 원장 기록 결과 |
| 공통 | 조회 기능 명세 작성 | 진위 조회·상품 조회 기능의 입력과 결과를 문서로 정리 |
| 공통 | 작업 이력 | 누가 무엇을 등록했는지 남김 |

## 완료 기준 (Definition of Done)

| # | 기준 |
| --- | --- |
| 1 | 관리자가 고유번호를 등록하면 원장에 기록되고 기록 번호가 서비스에 남는다 |
| 2 | 같은 고유번호는 재등록되지 않는다 |
| 3 | 일반 유저가 칩이 부착된 제품의 칩을 스캔하면 서명 검증과 원장 대조에 따른 진위 결과가 나오고, 고유번호를 직접 입력하거나 서명 없는 QR을 스캔하면 원장 등록 여부가 나온다 |
| 4 | 기록 완료되지 않은 등록 건은 플랫폼에 노출되지 않는다 |
| 5 | 연동 대상 블록체인만 교체해서 다른 블록체인으로 붙일 수 있다 |

## Phase 1 이후의 진입 계획 (사업 계획 기준)

사업 계획서(모두의 창업 지원서)에 제출한 단계별 계획이며, 금액과 목표는 검증 전의 계획값이다. 원문 요약은 `원천자료/03-모두의창업 지원서 요약.md`를 따른다.

| 단계 | 시기 | 대상 | 내용 | 이 문서의 Phase |
| --- | --- | --- | --- | --- |
| 1단계 신뢰도 확보 | 착수~6개월 | 자체 검수 인프라가 없는 소규모 위탁판매점·병행수입 셀러 1~2곳(첫 파트너, 무료 또는 최소 비용) | QR/NFC 태깅, 블록체인 등록, 검증 전 과정을 실거래 환경에서 검증하고 정량 실적 확보. 제3자 감정사 네트워크 구축 | Phase 1 (파트너는 서비스 안에서 직접 등록하지 않고 운영사가 등록을 대행) |
| 2단계 유료화·브랜드 확대 | 6개월~1년 | K패션 디자이너 브랜드 1~2곳, 이들의 공식 중고 판매 채널 | 브랜드 인증 발급비 유료화, 공식 중고 채널에 API 연동해 거래 시점 검증 수수료 | Phase 2 시작 |
| 3단계 규모 확대 | 1년 이후 | K패션 브랜드 3~5곳 추가, 소규모 위탁판매점, 중소 리셀 플랫폼 | 검수 인프라 대체 월 구독 서비스, 중소 리셀 플랫폼 API 연동 확대 | Phase 2 이후 |

* **등록 근거**: 신규 제품은 제조사 협력으로, 기존 제품은 제조사 영수증이나 전문가 감정으로 진위를 확인한 뒤 운영사가 원장에 기록한다는 계획이다. Phase 1은 신규 제품만 등록하고 기존 제품은 추후 검토한다. 확인 기준과 책임은 정해지지 않았다.
* **장기 방향**: 회사가 성장하면 제조사가 생산 단계부터 직접 고유 인증정보를 발급하고 기록한다. 이때 1차 판매, 중고·리셀 거래, 소유권 이전 모든 시점에서 원본 데이터와 대조한다.
* **초기 대상**: 글로벌 명품 브랜드가 아니라 국내 K패션 디자이너 브랜드(월 생산 1,000~5,000개 규모)와 리셀 거래 시장이다.
