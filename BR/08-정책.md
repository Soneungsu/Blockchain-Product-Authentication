# 정책

정책 규칙 한 줄(하나의 허용·금지·조건·기준)마다 하나의 `POLICY-###`를 부여한다. 번호 부여 기준은 `규칙/01-ID 스키마.md` §12를 따른다.

| ID | 정책 | 근거 |
| --- | --- | --- |
| POLICY-001 | 제품의 진위와 소유는 원장 기록을 기준으로 판단한다. 가격·호가·결제처럼 자주 바뀌는 정보는 서비스 자체 저장소에서 관리한다 | `03-범위.md` |
| POLICY-002 | 원장 기록이 완료된 등록 건만 플랫폼에 노출한다 | `03-범위.md` |
| POLICY-003 | 원장에 한번 기록된 내용은 수정·삭제하지 않고 추가로만 남긴다 | `03-범위.md` |
| POLICY-004 | Phase 1의 원장 기록 유형은 '등록'과 '무효'로 한정한다. Phase 2에서 '판매 등록', '판매 완료', '소유권 이전' 기록을 추가한다 | `03-범위.md` |
| POLICY-005 | 고유번호는 원문이 아닌 복원할 수 없는 변환값(해시+salt)으로 저장한다. 유저는 익명 ID만 사용한다 | `03-범위.md` |
| POLICY-006 | 원장 기록이 연결된(등록 완료된) 상품은 수정·삭제할 수 없다. 원장 기록이 연결되지 않은 상품은 자유롭게 수정·삭제할 수 있다 | `03-범위.md`, OI-011 |
| POLICY-007 | 고유번호 형식 검증 기준은 브랜드/상품별로 다를 수 있다. Phase 1에서는 최소 형식 검증만 수행한다 | `03-범위.md`, OI-008 |
| POLICY-008 | 관리자는 원장 기록을 요청하기 전 최종 확인 화면에서 등록 내용을 확인해야 한다. Phase 1에서는 이 확인 화면 외의 추가 오입력 방지 수단(이중 입력 등)을 두지 않는다 | `03-범위.md`, OI-010, OI-015 |
| POLICY-009 | 원장 기록 실패 건은 관리자가 직접 재시도하며, 재시도 횟수를 제한하지 않는다 | `03-범위.md`, OI-012 |
| POLICY-010 | 잘못 등록된 고유번호는 기존 등록 기록을 수정·삭제하지 않고 '무효' 기록을 추가하는 방식으로 처리한다. 무효 처리된 건은 플랫폼 노출에서 제외한다 | `03-범위.md`, OI-010 |
| POLICY-011 | 고유번호별 진위 조회 횟수를 기록하여 관리자가 확인할 수 있게 한다. Phase 1에서는 알림·통계 대시보드 기능은 두지 않는다 | `03-범위.md`, OI-006 |
| POLICY-012 | 진위 조회 결과는 원장 대조 결과를 '정품'으로 명시하여 표시한다. 결과 유형은 정품/무효 처리됨/미등록 3종으로 한다 | `03-범위.md`, OI-007 |
| POLICY-013 | 원장 연동 블록체인은 이더리움(EVM 계열)으로 시작하며, 다른 EVM 호환 체인(L2 포함)으로 교체할 수 있는 구조를 유지한다 | `03-범위.md`, OI-002 |
| POLICY-014 | 내부 기획 문서에서는 시장 분석 목적으로 경쟁 플랫폼 실명을 언급할 수 있다. 단, 특정 브랜드의 부정적 사례(가품 피해 등)를 인용할 때는 공개된 보도 자료를 출처로 명시해야 한다 | `02-서비스배경.md`, OI-001 |
| POLICY-015 | 대외 공개 자료(마케팅, 투자 유치 자료 등)에서는 경쟁 플랫폼 실명 대신 일반화된 표현을 사용하고, 공개 시점에 법무 검토를 거친다 | `02-서비스배경.md`, OI-001 |
